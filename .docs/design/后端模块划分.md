# 代理网关模板设计

## 核心逻辑

**项目用于在本地实验不同上游服务，采用 Web 前端与 JavaScript 后端，支持 Docker 部署和直接通过 Node.js 启动。**

模板提供下游接口、本地功能、消费者调度和最简 SPA。具体服务负责上游资源、上游通信、请求转化、响应转化及响应处理规则。

下文以代码格式引用的 Markdown 路径均相对此目录，仅指向本地文档，不纳入版本控制。

- `调度实现.md`：队列、消费者和执行规则
- [模板使用说明](../../DOCUMENTS/模板使用说明.md)：服务接入接口与使用方式
- [适配需求清单](../../DOCUMENTS/适配需求清单.md)：接入具体服务时需要确定的问题
- `../wanto/模板细节确认.md`：下游响应与日志约定
- [源码索引](../../src/README.md)：文件组织

## 模块职责

### I/O 模块

| 模块       | 职责                                         | I/O 边界           |
| ---------- | -------------------------------------------- | ------------------ |
| 下游对接   | 接收下游请求，向对应客户端返回响应           | 下游 HTTP 收发     |
| 上游对接   | 调用具体服务并接收上游响应                   | 上游通信           |
| 磁盘 I/O   | 提供文件读取、写入等单一操作，供其他模块调用 | 文件系统           |
| 控制台对接 | 向前端提供运行数据和管理操作                 | 后端面向前端的接口 |
| 日志打印   | 按统一格式输出运行事件                       | 终端或 Docker 日志 |

### 内部模块

| 模块         | 职责                                                 |
| ------------ | ---------------------------------------------------- |
| 下游请求转化 | 根据下游请求和模型 ID 构造具体服务所需的数据         |
| 上游响应转化 | 将上游响应转化为下游协议所需的结构                   |
| 上游资源管理 | 管理凭证、账号、消费者及其对应关系，维护资源可用状态 |
| 并发处理     | 管理队列顺序、请求锁定和消费者占用，派发待执行请求   |
| 流式处理     | 处理流式与非流式交付之间的差异及响应聚合             |
| 模型管理     | 提供模型清单，校验下游请求的模型 ID                  |

**请求转化与响应转化分别处理一个方向的数据，彼此解耦。** 内部模块所需的文件和网络操作通过对应 I/O 模块完成。

**上游仅支持流式、下游要求非流式时，网关收集上游响应，拼接完成后返回。** 具体上游的响应转化方式由服务适配实现。

错误处理与日志记录贯穿各模块。响应处理规则决定如何应对，日志模块负责记录事件。

## 下游接口

| 方法 | 路径                   | 行为                               |
| ---- | ---------------------- | ---------------------------------- |
| POST | `/v1/chat/completions` | OpenAI Chat Completions 格式的对话 |
| POST | `/v1/messages`         | Anthropic Messages 格式的对话      |
| GET  | `/v1/models`           | 返回模型清单                       |
| GET  | `/health`              | 返回网关自身的运行状态             |

对话接口通过请求中的 `stream` 字段选择流式或非流式交付。

**模板只校验 JSON 对象、非空模型 ID、模型白名单和流式开关，其他业务参数由具体服务处理。** OpenAI 的 `stream: null` 通过校验并保留原值。

**模型列表请求带有 `anthropic-version` 头时返回 Anthropic 格式，其余情况返回 OpenAI 格式。** 两种格式使用同一份模型清单。

健康检查返回 HTTP `200` 和 `{"status":"ok"}`，表示网关自身正常运行。上游连通性和资源状态由具体服务适配管理。

## 模型管理

### 模型清单

**模板只内置 `[${服务名}]Gateway-Test`，普通模型由 `service.additionalModels` 在代码中显式提供。模型清单同时作为调用白名单，每个普通模型 ID 对应请求转化中的处理方式。**

| 模型 ID                   | 行为                                  |
| ------------------------- | ------------------------------------- |
| `[${服务名}]Gateway-Test` | 在本地返回 `OK`，随后异步保存请求记录 |

测试模型 ID 由 `UPSTREAM_SERVICE_NAME` 生成。下游模型与上游资源分离，映射由下游请求转化实现；上游可以不提供模型参数。

**不在清单中的模型 ID 返回 `404 Not Found : Invalid Model ID`，记录 `request.rejected`。** 模型清单中未知的创建时间记为 `0`。

### 本地测试

**测试模型先按调用方的协议和 `stream` 参数返回 `OK`，再异步保存完整请求记录。** token 用量记为 `0`。模型列表、健康检查和测试模型在本地完成，不占用消费者。

**测试请求已完整接收并识别为测试模型时，即使下游在 `OK` 写完前断开，也继续保存该请求。**

请求记录保存到 `data/test_history/`，包含请求方法、原始路径及查询参数、请求头和完整正文。内存快照保留原始请求体字节；写入时将正文解析为 JSON，再按 2 个空格缩进，以 UTF-8 显示 Unicode 字符与符号，保留字符串内必要的 `\n`、引号和反斜杠转义。无法解析时回退到原字节。请求行与请求头按快照保存，不重算 `Content-Length` 等字段；记录用于阅读，不作为原样重放的 HTTP 报文。

文件名使用进程本地时间，格式为 `YYYY-MM-DD-HH-mm-ss.txt`。同秒重名时追加 `-001`、`-002` 等序号。

**保存失败时只记录失败日志。**

## 消费者调度

### 消费者与队列

消费者是同一时刻承接一个请求的逻辑执行单元。上游资源管理提供消费者并维护可用状态，并发处理维护占用状态。

**需要上游执行的请求先入队，由空闲且可用的消费者锁定并执行；执行期间条目保留在队列中。**

- 队列按首次入队顺序派发尚未锁定的请求。
- `REQUEST_QUEUE_CAPACITY` 默认 `32`，等待和锁定中的条目共同占用容量。
- 队列已满时返回 `429 Too Many Requests : Out of Request Queue Capacity`，记录 `request.rejected`。
- 请求成功完成或遇到不可重试错误时，立即清除条目。

### 再次执行

**只有旧消费者明确不可用时，才允许解锁仍需继续执行的请求；此时旧消费者在网关内的本轮执行已经结束。** 解锁保留原位，继续按首次入队顺序等待。

再次派发还要求下游连接有效、请求未取消或终结、尚未发送响应，并且仍有可用的重试次数。

**`RETRY_TIMES` 限制同一请求的额外重试轮次，默认 `0`。首次执行不占用重试次数；每次解锁后重新被消费者锁定，计为一轮重试。**

例如，`RETRY_TIMES=0` 时只执行首次的一轮；设为 `1` 时最多执行首次及一轮重试。**需要再次派发但重试次数已经用尽时，终结请求、清除队列条目并返回 `429 Too Many Requests : Retry Limit Exceeded`。记录 `request.terminated`，原因为“重试次数已用尽”；本轮执行仍按实际结果记录自己的结束事件。**

具体服务决定是否采用重试、账号切换或回退。**已向下游发送响应后，本轮执行失败则结束当前响应，不再派发。**

### 请求生命周期

同一请求的内部 UID 保持不变，并与客户端连接对应。每次消费者执行分别记录轮次，旧轮次迟到的数据和结束通知对当前轮次无效。

**下游取消或断开后，立即清除队列条目；已经开始的消费者继续执行，保持占用至本轮结束，后续响应直接丢弃。**

**取消后的本轮执行无论成功还是失败，均按结束处理，不再派发给其他消费者。** 结束日志使用 `execution.safefinished`，统计仍按实际执行结果记录。

### 超时

**空闲超时和整体超时均面向上游。每次上游调用重新计时，网关内部排队不设置超时。**

| 配置                            | 默认值   | 计时方式                                                       |
| ------------------------------- | -------- | -------------------------------------------------------------- |
| `REQUEST_IDLE_TIMEOUT_SECONDS`  | `300` 秒 | 实际发起上游调用时开始，每次收到上游数据后重置，至该次响应结束 |
| `REQUEST_TOTAL_TIMEOUT_SECONDS` | `600` 秒 | 实际发起上游调用时开始，限制该次调用总时长                     |

模板识别上游超时并通知本轮执行，由具体服务决定终结请求或继续尝试。解锁和再次派发遵守[再次执行](#再次执行)的条件。

### 网关关闭

**关闭时按消费者不可用的标准结束执行中的请求，完成本轮收尾并解除锁定，再清空队列，向下游返回 `503`。** 已开始流式响应的请求通过当前协议的流内错误结束连接。

**关闭响应使用 `503 Service Unavailable : Gateway Is Stopping`，记录 `request.terminated`，原因为“网关关闭”。关闭等待已接收测试请求的保存完成或失败；保存失败仍只记录 `test.save_failed`。**

**执行收尾或资源释放失败时，记录 `gateway.stop_failed`，保持停止状态并继续完成不依赖失败步骤的清理；只有全部关闭步骤完成才记录 `gateway.stopped`。** 关闭入口响应进程关闭信号，等待执行与 I/O 收尾，流程见`网关关闭.md`。

**关闭时直接断开尚未形成请求的连接，已有完整请求仍按既定流程收尾。Docker 停止时一直等待，必要时由用户手动强制结束。**

详细调度规则见`调度实现.md`。

## 响应处理

### 上游响应处理协议

**具体服务维护响应处理协议，根据上游响应码和原因短语，将响应标记为成功或失败，并为不同响应编写相应的处理方式。**

**执行统计和结束日志按消费者本轮的最终结果记录。** 下表的统计归类适用于本轮以该结果结束的情况。

| 识别结果                     | 处理                                   | 统计归类 |
| ---------------------------- | -------------------------------------- | -------- |
| 协议识别为成功               | 按服务规则转化并交付结果               | 成功     |
| 协议识别为失败               | 按对应规则报错、继续尝试或处理资源状态 | 失败     |
| 响应码或原因短语未被协议涵盖 | 一般直接透传给下游                     | 未知异常 |

**未知异常指响应处理协议未涵盖的响应码或原因短语。** 例如，上游可能返回 `403 Forbidden`、`429 Resource Exhausted` 或其他组合，具体服务按实际响应维护规则。

上游错误默认透传，特殊处理由具体服务决定。调用未获得上游响应等情况也由具体服务确定处理方式。任何再次派发均遵守消费者调度约束。

### 内部执行异常

**服务执行函数意外抛错，既未交回可用结果，也无上游响应可透传时，按本轮失败结束，清除请求并释放消费者。尚未开始响应时，向下游返回 `500 Internal Server Error : Internal Execution Error`。**

服务已经接管的网络错误、超时等仍按服务规则处理。该兜底情况记录 `execution.failed`；下游已经取消时按既定规则记录 `execution.safefinished`，统计仍计为失败。已经开始的响应通过对应协议的流内错误或中断结束。

### 下游响应表

下表用 `code` 表示数值响应码，`status` 表示原因短语，`message` 表示具体说明。响应内容按调用方的 OpenAI 或 Anthropic 协议封装。

| 场景                       | code  | status                  | message                         |
| -------------------------- | ----- | ----------------------- | ------------------------------- |
| 请求体格式错误             | `400` | `Bad Request`           | `Invalid Request Body`          |
| 队列容量已满               | `429` | `Too Many Requests`     | `Out of Request Queue Capacity` |
| API Key 校验失败           | `403` | `Forbidden`             | `Invalid API Key`               |
| 模型 ID 不存在             | `404` | `Not Found`             | `Invalid Model ID`              |
| 重试次数已经用尽           | `429` | `Too Many Requests`     | `Retry Limit Exceeded`          |
| 地址、资源或重置指标不存在 | `404` | `Not Found`             | `Resource Not Found`            |
| 请求方法不匹配             | `405` | `Method Not Allowed`    | `Invalid Request Method`        |
| 网关关闭                   | `503` | `Service Unavailable`   | `Gateway Is Stopping`           |
| 内部执行异常               | `500` | `Internal Server Error` | `Internal Execution Error`      |

**请求体格式错误、队列容量已满、API Key 校验失败、模型 ID 不存在、地址或资源不存在及请求方法不匹配均记录 `request.rejected`。** 无效重置指标按资源不存在处理，`405` 响应保留 `Allow` 头。

已开始发送响应时，错误通过对应协议的流内错误或中断交付。

## 控制台

**控制台采用最简 SPA，包含运行概览和独立的模型列表。**

**控制台数据查询与统计重置均免鉴权。运行概览在页面打开时读取，此后每 5 秒刷新；模型清单在页面加载时读取一次。**

### 运行概览

| 项目                | 展示内容                                                            |
| ------------------- | ------------------------------------------------------------------- |
| 服务名              | 上游服务名                                                          |
| 当前队列长度        | 当前队列条目数 / 队列容量上限，条目数包含等待和锁定中的请求         |
| 可用消费能力        | 当前空闲的可用消费者数 / 全部可用消费者数，分母包含忙碌的可用消费者 |
| 上游平均延迟（72H） | 本轮执行开始至首次收到上游数据的平均耗时                            |
| 请求平均耗时（72H） | 本轮执行开始至结束的平均耗时                                        |
| 请求成功率（72H）   | 按本轮执行结果统计的成功比例                                        |

例如，队列有 5 个等待请求和 2 个锁定请求，容量为 32 时，队列长度显示 `7/32`；3 个可用消费者中有 1 个空闲时，可用消费能力显示 `1/3`。

### 统计单位

**三个 72H 指标以消费者每次锁定请求后的一轮执行为统计单位。** 一轮执行对应一个独立样本，锁定请求时开始记录，本轮结束时记录执行结果。

同一请求再次被消费者锁定时，产生新的独立样本。例如，同一请求先后被锁定两次，就分别统计这两轮执行。

消费者封装具体服务的通信方式与内部调用过程。统计使用本轮执行的开始、首份上游数据、结束和执行结果，具体服务内部的调用次数不改变样本数量。

样本只覆盖本轮执行阶段，排队等待不计入耗时。模型列表、健康检查和本地测试模型不经过消费者执行，不产生统计样本。

### 指标记录

| 指标         | 采集时点                                   | 更新时点   |
| ------------ | ------------------------------------------ | ---------- |
| 上游平均延迟 | 首次收到上游数据时，记录本轮开始至此的耗时 | 本轮结束后 |
| 请求平均耗时 | 本轮结束时，记录本轮总耗时                 | 本轮结束后 |
| 请求成功率   | 本轮结束时，按响应处理协议记录实际结果     | 本轮结束后 |

**延迟值在首份数据到达时记录，本轮结束后才更新平均值。即使本轮随后失败，已经取得的延迟值仍纳入统计；始终未收到数据的执行不计入延迟平均值。**

### 按日结果表

**三个指标统一归入本轮执行结束当天的 UTC 日期，保留今天和前两天。** 每天 UTC 00:00 淘汰最旧一天，增加空白的新一天，保留另外两天。

请求结果维护三天 × 四项数据。表中的“请求”指消费者每次锁定后的一轮执行，每轮结束时计入结束当天的 UTC 日期。

| 字段       | 内容                                         |
| ---------- | -------------------------------------------- |
| 总请求数   | 当天已结束的执行总数                         |
| 成功数     | 响应处理协议判定为成功的执行数               |
| 失败数     | 响应处理协议判定为失败的执行数               |
| 未知异常数 | 响应码或原因短语未被响应处理协议涵盖的执行数 |

每轮执行只计入成功、失败、未知异常中的一类，总请求数为三类计数之和。下游取消后继续完成的执行，仍按本轮实际结果计数。

**成功率 = 三天成功数合计 ÷ 三天总请求数合计，未知异常计入总数。**三天总请求数为 `0` 时，显示 `??%`。

### 重置

三个指标各自在末尾提供独立的重置按钮：

- **成功率**：清空三天结果表的全部计数
- **上游平均延迟**：只清空该指标的已有统计
- **请求平均耗时**：只清空该指标的已有统计

**重置不停止消费者，也不修改请求队列。正在执行的请求继续运行，重置后新产生的统计结果正常计入。**

统计不跨重启保留，重启后清零。上游平均延迟和请求平均耗时两个指标没有样本时，均显示 `—`。

逐条运行事件通过终端或 Docker 日志查看。

## 日志

### 格式

**日志使用统一格式，事件标识、附加参数和中文说明模板按下方事件清单定义。**

```text
[时间] [级别] [事件标识] 事件说明
```

- 时间：UTC 毫秒时间，格式为 `YYYY-MM-DDTHH:mm:ss.SSSZ`。
- 级别：`INFO`、`WARN`、`ERROR`。
- 事件标识：固定的 `模块.事件` 名称，与事件类型一一对应。
- 事件说明：使用统一中文模板，将附加参数填入说明。

调用方提供事件和参数，日志模块组织输出，每条日志以换行结束。各事件的附加参数以说明模板中的占位符为准。

**日志格式化或写出失败时，业务继续处理，标准错误只输出一次诊断，最终采用失败退出状态。** 输出与写出等待见`统一日志输出.md`。

### 执行结束事件

**每轮执行结束只记录一个结束事件。下游已取消时，统一记录安全结束；其余情况按本轮结果选择完成、失败或未知响应。**

| 情况                                 | 事件                     |
| ------------------------------------ | ------------------------ |
| 下游已取消，本轮已经结束             | `execution.safefinished` |
| 下游未取消，结果为成功               | `execution.completed`    |
| 下游未取消，结果为失败               | `execution.failed`       |
| 下游未取消，响应处理协议未覆盖该响应 | `execution.unkownresult` |

安全结束的统计仍按本轮实际成功、失败或未知异常记录。

### 事件清单

| 事件标识                 | 触发条件                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| `gateway.started`        | 网关成功开始监听                                                                                 |
| `gateway.start_failed`   | 网关初始化或监听失败                                                                             |
| `gateway.stopping`       | 网关开始关闭，停止接收和派发请求                                                                 |
| `gateway.stopped`        | 关闭流程完成                                                                                     |
| `gateway.stop_failed`    | 执行收尾或资源释放等关闭步骤明确失败                                                             |
| `request.queued`         | 请求进入队列                                                                                     |
| `execution.started`      | 消费者锁定请求，开始本轮执行                                                                     |
| `execution.completed`    | 未取消的请求执行成功                                                                             |
| `execution.failed`       | 未取消的请求执行失败                                                                             |
| `execution.unkownresult` | 未取消的请求得到响应处理协议未覆盖的响应                                                         |
| `execution.safefinished` | 被取消的请求本轮执行结束                                                                         |
| `request.rejected`       | 请求体格式错误、队列容量已满、API Key 校验失败、模型 ID 不存在、地址或资源不存在、请求方法不匹配 |
| `request.terminated`     | 请求因客户端断开、网关关闭等原因提前终结；上游超时仅在实际终结请求时记录                         |
| `consumer.available`     | 消费者开始可用或恢复可用                                                                         |
| `consumer.unavailable`   | 消费者失去可用资源                                                                               |
| `test.saved`             | 测试请求异步保存成功                                                                             |
| `test.save_failed`       | 测试请求异步保存失败                                                                             |
| `stats.reset`            | 对应统计被重置                                                                                   |

### 说明模板

| 事件标识                 | 级别    | 说明模板                                                                           |
| ------------------------ | ------- | ---------------------------------------------------------------------------------- |
| `gateway.started`        | `INFO`  | `启动成功，开始监听 ${address}:${port}`                                            |
| `gateway.start_failed`   | `ERROR` | `启动失败：${reason}`                                                              |
| `gateway.stopping`       | `INFO`  | `进程停止中`                                                                       |
| `gateway.stopped`        | `INFO`  | `进程已停止`                                                                       |
| `gateway.stop_failed`    | `ERROR` | `停止失败：${reason}`                                                              |
| `request.queued`         | `INFO`  | `新请求${uid}：${protocol}\|${model}`                                              |
| `execution.started`      | `INFO`  | `消费者${consumerId}：请求${uid}（第${attempt}轮）开始执行`                        |
| `execution.completed`    | `INFO`  | `消费者${consumerId}：请求${uid}（第${attempt}轮）执行完成`                        |
| `execution.safefinished` | `INFO`  | `消费者${consumerId}已完成被取消的请求${id}`                                       |
| `execution.failed`       | `WARN`  | `消费者${consumerId}：请求${uid}（第${attempt}轮）执行失败：${reason}；${action}`  |
| `execution.unkownresult` | `WARN`  | `消费者${consumerId}：请求${uid}（第${attempt}轮）收到未知响应：${code} ${status}` |
| `request.rejected`       | `WARN`  | `请求${uid}被拒绝：${reason}`                                                      |
| `request.terminated`     | `WARN`  | `请求${uid}提前结束：${reason}`                                                    |
| `consumer.available`     | `INFO`  | `消费者${consumerId}已可用`                                                        |
| `consumer.unavailable`   | `WARN`  | `消费者${consumerId}已不可用：${reason}`                                           |
| `test.saved`             | `INFO`  | `已将测试请求${uid}保存至${path}`                                                  |
| `test.save_failed`       | `ERROR` | `测试请求${uid}保存失败：${reason}`                                                |
| `stats.reset`            | `INFO`  | `${metric}已重置`                                                                  |

`${uid}` 和安全结束说明中的 `${id}` 都指内部请求 UID。`${attempt}` 为执行轮次；`${action}` 为实际处理结果，例如“已解锁，等待其他消费者接手”或“已终结请求”。未知响应事件的 `${code}` 和 `${status}` 保留上游实际响应码和原因短语。

## 启动配置

**根目录 `.env` 保存启动配置，[.env.example](../../.env.example)提供示例。**

启动阶段创建配置、模型清单、请求队列、统计初值和生命周期状态，完成异步服务初始化并登记消费者变更通知。函数与状态归属见`启动与初始化.md`。

| 变量                            | 用途                               | 默认值                 |
| ------------------------------- | ---------------------------------- | ---------------------- |
| `PORT`                          | HTTP 监听端口，地址为 `0.0.0.0`    | `8800`                 |
| `GATEWAY_API_KEY`               | 下游访问网关的 API Key             | 空值                   |
| `UPSTREAM_SERVICE_NAME`         | 上游服务名，用于生成测试模型 ID    | `default_service_name` |
| `REQUEST_QUEUE_CAPACITY`        | 等待和锁定条目的总容量             | `32`                   |
| `RETRY_TIMES`                   | 同一请求首次执行之外允许的重试轮次 | `0`                    |
| `REQUEST_IDLE_TIMEOUT_SECONDS`  | 每次上游调用的空闲超时，单位为秒   | `300`                  |
| `REQUEST_TOTAL_TIMEOUT_SECONDS` | 每次上游调用的整体超时，单位为秒   | `600`                  |

**密钥为空时，下游未传密钥或传入任意密钥均可通过。** 密钥非空时，对话接口和模型列表要求匹配，支持 `Authorization: Bearer <密钥>` 和 `x-api-key`。首页、健康检查以及控制台数据查询和统计重置免鉴权。
