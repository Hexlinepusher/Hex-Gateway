# 代理网关模板设计

## 目标与边界

项目用于在本地实验不同上游服务。应用采用 Web 前端与 JavaScript 后端，支持 Docker 部署和直接通过 Node.js 启动。

模板提供本地能力和基于消费者约定的公共协作逻辑。具体服务提供消费者、上游通信和服务相关的数据转化。前端保留空白页面，控制台操作在明确需求后设计。

## 模块职责

| 模块         | 职责                                             | I/O 边界                          |
| ------------ | ------------------------------------------------ | --------------------------------- |
| 下游对接     | 接收请求，绑定客户端连接，按照下游协议写出响应。 | HTTP 收发。                       |
| 上游对接     | 调用具体服务并接收上游数据。                     | 上游通信。                        |
| 磁盘 I/O     | 提供文件读取、写入等原子操作，返回结果或错误。   | 文件系统。                        |
| 控制台对接   | 向管理前端提供管理操作与数据。                   | 后端面向前端的接口。              |
| 日志打印     | 统一输出运行事件。                               | 日志输出通道。                    |
| 下游请求转化 | 根据下游请求和模型 ID 构造具体的上游调用数据。   | 内存处理。                        |
| 上游响应转化 | 将上游结果和错误转化为下游所需的数据。           | 内存处理。                        |
| 上游资源管理 | 管理凭证、账号和消费者的对应关系及可用状态。     | 文件和网络操作交由对应 I/O 模块。 |
| 并发处理     | 管理请求队列、请求取消和向空闲消费者派发请求。   | 内存处理。                        |
| 流式处理     | 处理响应交付方式的差异及必要的聚合状态。         | 实际数据收发交由对接模块。        |
| 模型管理     | 维护下游模型清单，提供列表和模型 ID 判断。       | 内存处理。                        |

请求转化与响应转化分别处理一个方向的数据。错误处理与日志记录是贯穿各模块的约定，实际日志打印集中到统一的 I/O 模块。

## 下游接口

| 方法 | 路径                 | 行为                                 |
| ---- | -------------------- | ------------------------------------ |
| POST | /v1/chat/completions | OpenAI Chat Completions 格式的对话。 |
| POST | /v1/messages         | Anthropic Messages 格式的对话。      |
| GET  | /v1/models           | 返回网关向下游公布的模型。           |
| GET  | /health              | 返回网关自身的运行状态。             |

对话接口通过请求中的 stream 字段选择流式或非流式交付。

模型列表共用一份模型清单。请求带有 anthropic-version 头时返回 Anthropic 格式，其余情况返回 OpenAI 格式。

健康检查表达网关自身的状态。上游连通性与账号额度由具体服务适配管理。

## 模型管理

下游 model 是网关提供的调用选项标识。模型清单由每个网关人工维护，模型映射由下游请求转化模块实现。

清单中公布的每个模型 ID 均具有明确的处理方式。映射目标可以是上游模型、固定 agent 或一种无需模型参数的调用方式。

每个网关固定提供以下两个模型：

| 模型 ID              | 行为                                  |
| -------------------- | ------------------------------------- |
| <上游服务名>-default | 按具体服务的设计完成实际上游调用。    |
| <上游服务名>-test    | 保存完整原始请求，在本地返回内容 OK。 |

固定模型 ID 由上游服务名生成，其他模型由具体网关人工维护。

测试模型的响应遵循调用方选择的对话协议和 stream 参数。模型列表、健康检查和测试模型在本地完成。

## 原始请求记录

测试模型将原始请求保存到 data/test_history/。内容包含请求方法、原始路径及查询参数、请求头和未经解析改写的请求体。

文件名使用 YYYY-MM-DD-HH-mm-ss.txt。同一秒有多个记录时追加 -001、-002 等序号，以独占创建方式避免覆盖已有记录。

业务模块组织记录内容和文件名，磁盘 I/O 模块执行文件操作。记录成功后返回测试响应；记录失败按本地错误处理。

## 消费者与并发

消费者是同一时刻承接一个请求的逻辑执行单元。上游资源管理决定消费者与资源的对应关系。

例如，一个凭证允许十路并发时可以提供十个消费者，一个账号只允许单路执行时可以提供一个消费者。

需要上游执行的对话请求统一先进入进程内队列，由空闲且可用的消费者领取。每条请求在同一执行轮次内只交给一个消费者。

上游资源管理维护消费者的空闲、占用和不可用状态。并发处理按照等待顺序派发请求，移除已取消的排队请求。

消费者在实际执行结束或确认终止后才能重新空闲。流式响应的首次输出表示执行仍在进行。

## 请求标识与生命周期

网关接受请求时生成内部 UID。UID 在排队、执行、重排、完成、失败、取消和超时处理过程中保持不变。

请求上下文绑定客户端连接、UID、开始时间、整体截止时间及执行状态。响应归属由该绑定确定。

同一请求重新派发时区分执行轮次。旧轮次的迟到数据和结束通知对当前轮次无效。

客户端断开或取消后，排队请求从队列移除，执行中的请求通知对应执行流程取消。

## 超时

启动配置使用秒作为超时单位。

| 变量                          | 默认值 | 语义                                                   |
| ----------------------------- | ------ | ------------------------------------------------------ |
| REQUEST_IDLE_TIMEOUT_SECONDS  | 300    | 从实际开始上游调用时计时，每次收到上游响应数据后重置。 |
| REQUEST_TOTAL_TIMEOUT_SECONDS | 600    | 从网关接受对话请求时计时，覆盖排队、执行和响应交付。   |

整体计时持续至请求完成。重排保持原来的整体截止时间。排队时间计入整体超时；上游空闲计时在实际执行时启动。

排队超时移除请求并向下游报错。执行超时向下游报错并通知取消，消费者在实际执行终止后释放。已经开始流式交付时按流内错误规则结束。

本地请求使用整体生命周期约定，上游空闲计时适用于上游调用。

## 资源失效与重排

具体服务负责识别资源失效、停用相关消费者并决定是否重排。例如账号额度耗尽时，该账号关联的消费者停止领取新请求。

模板提供重新入队的协作能力。重排的请求保持原来的 UID、客户端连接和整体截止时间。

请求重排需要同时满足：

1. 客户端连接仍然有效。
2. 请求尚未取消或整体超时。
3. 下游响应尚未提交。
4. 前一执行轮次已经结束或确认终止。

具体服务决定自动重试、账号切换和回退策略。

## 错误处理

上游明确返回错误时，保留能够对应的 HTTP 状态码和上游错误信息，按下游协议组织响应。HTTP 状态码与上游业务错误码分别处理。

网关自身的错误根据本地原因报告，例如未知模型和请求格式不合法。调用失败且没有上游响应时，由网关报告调用失败。

已开始响应后，错误通过当前下游协议允许的流内报错或中断方式结束。所有错误路径完成请求收尾，消费者释放遵循实际执行终止的约定。

## 日志

各模块调用统一日志接口，提供级别、事件名称和附加信息。级别包括普通事件、警告和错误。请求相关事件携带内部 UID。

日志模块统一补充时间、组织输出格式并写入输出通道。日志记录覆盖正常请求和异常事件。应对措施由相关业务模块决定。

## 启动配置

根目录 .env 保存启动配置，.env.example 提供可填写的示例。

| 变量                          | 用途                                           |
| ----------------------------- | ---------------------------------------------- |
| PORT                          | HTTP 监听端口，默认 3000，监听地址为 0.0.0.0。 |
| GATEWAY_API_KEY               | 下游访问网关使用的 API Key。                   |
| UPSTREAM_SERVICE_NAME         | 上游服务名，用于生成固定模型 ID。              |
| REQUEST_IDLE_TIMEOUT_SECONDS  | 上游空闲超时，默认 300 秒。                    |
| REQUEST_TOTAL_TIMEOUT_SECONDS | 请求整体超时，默认 600 秒。                    |
