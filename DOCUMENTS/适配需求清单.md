# 适配需求清单

接入具体上游服务时，逐项确定服务的处理方式，并核对模板的统一约定。服务接口与使用方法见[模板使用说明](模板使用说明.md)。

## 设计问题

### 模型与请求转化

- [ ] 通过 `service.additionalModels` 在代码中明确提供普通模型清单。
- [ ] 确定各普通模型对应的上游资源或调用方式。
- [ ] 确定如何将下游请求转化为上游需要的参数和数据。

### 上游通信与响应转化

- [ ] 确定上游调用方式，以及每次调用的开始、数据到达和响应结束的识别方式。
- [ ] 确定如何报告本轮首份上游数据、执行结束及实际结果。
- [ ] 确定如何将上游响应分别转化为 OpenAI Chat Completions 和 Anthropic Messages 格式。

### 凭证、账号与消费者

- [ ] 确定凭证和账号如何存储、读取和使用，文件读写通过统一的磁盘 I/O 模块完成。
- [ ] 确定每个凭证或账号提供多少消费者，以及消费者与资源的对应关系。
- [ ] 确定资源的选择、轮询方式，以及资源失效的识别方式和相关消费者可用状态的维护方式。

### 响应处理与异常

- [ ] 按上游响应码和原因短语维护响应处理协议，明确哪些响应表示成功、哪些表示失败。
- [ ] 为已识别的失败响应确定处理方式，包括向下游报错、处理资源状态或继续尝试。
- [ ] 确定未获得上游响应、上游超时等异常如何终结请求或继续尝试。
- [ ] 确定是否采用账号切换、重试或回退，以及采用这些处理方式的条件。

### 流式与非流式交付

- [ ] 确定上游支持的响应形式，以及如何满足下游选择的流式或非流式交付。
- [ ] 上游仅支持流式时，确定如何收集并拼接响应，以满足下游的非流式请求。

### 关闭收尾

- [ ] 确定网关关闭时，如何结束消费者在网关内的本轮执行并完成收尾。

## 模板边界

接入时逐项核对以下模板规则。

- [ ] **模型清单**：作为调用白名单，由内置的 `[${服务名}]Gateway-Test` 与服务显式提供的普通模型组成；测试模型由模板在本地处理。
- [ ] **队列锁定**：执行期间保留队列条目并保持锁定，等待和锁定中的条目共同占用容量。
- [ ] **原位解锁**：只有旧消费者明确不可用、本轮执行已经结束时，才解锁仍需执行的请求；请求保留原位，按首次入队顺序等待。
- [ ] **再次派发**：下游连接有效，请求未取消或终结，尚未向下游发送响应，并且仍有可用的重试次数。已发送响应时，执行失败则结束当前响应。
- [ ] **重试上限**：`RETRY_TIMES` 默认 `0`，只计算首次执行之外的重试轮次；每次解锁后重新被消费者锁定计为一轮重试；需要再次派发但次数已用尽时返回 `429`。
- [ ] **下游取消**：立即清除队列条目，消费者继续执行至本轮结束，后续响应丢弃；无论结果如何，均不再派发。
- [ ] **上游超时**：每次上游调用重新计时，空闲超时在收到上游数据时重置；默认空闲 `300` 秒、整体 `600` 秒，网关排队不设置超时。
- [ ] **响应分类**：上游错误默认透传，特殊处理由具体服务决定；响应处理协议未涵盖的响应码或原因短语计为未知异常，一般直接透传。
- [ ] **结束日志**：每轮只记录一个结束事件；下游已取消时使用 `execution.safefinished`，其余情况按成功、失败或未知响应分别使用 `execution.completed`、`execution.failed`、`execution.unkownresult`。
- [ ] **执行统计**：以消费者每次锁定请求的一轮执行为单位，按本轮最终结果记录；取消后的执行仍按实际结果统计，排队时间不计入耗时，内部调用次数不改变样本数量。
- [ ] **数据采集**：首次收到上游数据时记录延迟值，本轮结束后更新平均值；各项统计统一归入本轮结束当天的 UTC 日期。
- [ ] **网关关闭**：先按消费者不可用的标准结束执行并解锁，再清空队列、向下游返回 `503`；已开始流式响应时，通过流内错误结束。

具体服务在发起上游调用时登记计时，并负责超时后的处理与清理。消费者调度与执行接口见[执行与取消](模板使用说明.md#执行与取消)。
